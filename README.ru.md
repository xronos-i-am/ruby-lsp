# ruby-lsp-hint

[In English](README.md)

Навигация по ruby-коду для Claude Code, оформленная пакетом: он объявляет языковой сервер `ruby-lsp`
и отбивает текстовый поиск по символьному имени, пока в сессии ни разу не позвали тул `LSP`.

Это две половины одной привычки. Объявление сервера делает так, что тул `LSP` отвечает; хук делает
так, что агент к нему идёт, — указатель в `CLAUDE.md` проигрывает рефлексу набрать `grep`. Отбой
срабатывает на первом шаге навигации, раньше первого открытого файла, и снимается до конца сессии
любым вызовом `LSP`, в том числе таким, который вернулся пустым.

## Что делает пакет

Самого языкового сервера в нём нет: `ruby-lsp` — гем, который ставите вы, а пакет лишь объясняет
Claude Code, как запускать уже имеющийся у вас бинарник.

| Часть | Что даёт |
| --- | --- |
| Объявление сервера, `lspServers.ruby-lsp` | Claude Code запускает ваш бинарник `ruby-lsp`, и тул `LSP` отвечает по `.rb`, `.rake`, `.gemspec`, `.ru` и `.erb`: определения, ссылки, hover, символы файла и воркспейса |
| `hooks/lsp-hint.sh` | `grep`, `rg`, `ack`, `ag`, `git log -S`, слэш-шаблон у `sed`/`awk`/`perl` и тул `Grep` отбиваются, пока шаблон — голое символьное имя; фраза в кавычках проходит |
| `skills/setup-ruby-lsp` | Разовая настройка: проверяет, что сервер может стартовать, ищет плагин, занявший те же расширения, и заводит проектный `docs/agents/ruby-lsp.md` |

## Требования

| Что | Минимум | Что будет ниже минимума |
| --- | --- | --- |
| Ruby | 3.0 | Нижняя граница самого `ruby-lsp` |
| Гем `ruby-lsp` | доступен командой `ruby-lsp` | Тул `LSP` не отвечает ничем, и своей ошибки сервер не даёт |
| `jq`, `bash` | любые | Хук — bash-скрипт, разбирающий вход через `jq`; без них падает каждый его вызов |
| Claude Code | 2.1.157 | Каталог-плагин под `.claude/skills/` не подхватывается, и объявление сервера, которое пишет APM, не читает никто |
| Claude Code | 2.1.275 | Только для однокомандной формы `/plugin install … --marketplace …` ниже; у двухшаговой формы такой границы нет |
| APM | 0.29.1 | Только для установки через APM: версии старше пишут конфигурацию LSP в корневой `.lsp.json` — путь, который Claude Code игнорирует, и тул молчит, ничем этого не объясняя |

Две версии, у которых есть граница, проверяются и поднимаются так:

```sh
claude --version
apm --version && apm self-update    # только при установке через APM
```

Ещё два условия, и ни одно не сообщает о себе, когда не выполнено:

- **Гем объявляется там, откуда его вернёт рутинная команда** — dev-группой `Gemfile`, — а не ставится
  руками:

  ```ruby
  group :development do
    gem "ruby-lsp", require: false
  end
  ```

  Смысл — держать сервер на той версии ruby, которая используется в проекте. Наборы гемов у менеджера
  версий свои на каждую версию, поэтому поставленный руками гем принадлежит той, что была активна в тот
  момент: стоит проекту перейти на другую — команды в её наборе нет, и сервер перестаёт стартовать.
  После смены версии `bundle install` возвращает его сам, ручная установка — нет. Падение при этом
  тихое: Claude Code гасит сервер после трёх неудачных стартов и больше не поднимает, так что
  единственным симптомом остаётся вызов `LSP`, которому не отвечает никакой сервер.
- **Проектному плагину нужны доверие к каталогу и сессия, запущенная из корня репозитория.** Из
  подкаталога он не загрузится, и до согласия в диалоге доверия — тоже.

## Установка через APM

1. Объявите зависимость:

   ```yaml
   # apm.yml
   dependencies:
     apm:
       - xronos-i-am/ruby-lsp-hint
   ```

2. `apm install`. Он печатает `Configured 1 LSP server` и строки хука, которые влил.
3. `/reload-plugins` или следующая сессия. Хуки читаются на старте сессии, поэтому отбой в любом случае
   начинает работать со следующей.
4. Один раз выполните скилл `setup-ruby-lsp` и закоммитьте написанный им `docs/agents/ruby-lsp.md`.

Что приезжает в проект:

```
.claude/skills/apm-lsp/.claude-plugin/plugin.json   объявление сервера, подхватывается само
.claude/settings.json                               строки хука, влиты APM
.claude/hooks/ruby-lsp-hint/hooks/                  скрипт хука и его устройство
.claude/skills/setup-ruby-lsp/                      скилл настройки и семя дока
```

Этими файлами владеет APM и перезаписывает их при следующей установке, поэтому правки живут в пакете
или в собственных файлах проекта, а не в выложенных копиях.

## Установка плагином Claude Code

Репозиторий заодно и маркетплейс из одного плагина, так что APM не обязателен. На этом пути в проект
не копируется ничего: Claude Code запускает плагин из его собственного каталога и сам раскрывает
`${CLAUDE_PLUGIN_ROOT}`.

1. **Добавьте маркетплейс.** Из шелла:

   ```sh
   claude plugin marketplace add xronos-i-am/ruby-lsp-hint
   ```

   В сессии тот же источник принимает `/plugin marketplace add xronos-i-am/ruby-lsp-hint`. Через
   `#<ref>` пинится ветка или тег. Пока репозиторий приватный, Claude Code клонирует его теми
   git-доступами, которые уже есть на машине, и ничего не спрашивает: для формы `owner/repo` он
   проверяет, аутентифицирует ли ваш ssh-ключ `github.com`, и при удаче клонирует по ssh.

2. **Поставьте плагин, выбрав, кому он достанется.** Из шелла, где по умолчанию — вам на этой машине:

   ```sh
   claude plugin install ruby-lsp-hint@xronos-i-am                   # вам, во всех проектах
   claude plugin install ruby-lsp-hint@xronos-i-am --scope project   # всем в этом репозитории
   claude plugin install ruby-lsp-hint@xronos-i-am --scope local     # вам, только в этом репозитории
   ```

   В сессии `/plugin install ruby-lsp-hint@xronos-i-am` открывает карточку плагина: видно, что он
   добавляет, и область выбирается там же. На Claude Code 2.1.275 и новее два шага сводятся в один, и
   плагин называется без половины после `@`:

   ```text
   /plugin install ruby-lsp-hint --marketplace xronos-i-am/ruby-lsp-hint
   ```

3. **Для репозитория важно, чего `--scope project` не делает.** Он пишет запись в `.claude/settings.json`,
   которую вы коммитите, и этим включает плагин коллегам — но не скачивает его на их машины. Команду
   установки каждый из них тоже выполняет один раз.

4. **Активируйте.** `/reload-plugins` или следующая сессия.

5. **Проверьте, что доехало.** `claude plugin list` печатает плагин с версией, областью и состоянием, а
   по `/` виден его скилл как `/ruby-lsp-hint:setup-ruby-lsp`. Выполните этот скилл один раз и
   закоммитьте написанный им `docs/agents/ruby-lsp.md`.

## На расширение — один сервер

Если ruby-сервер объявляет ещё один включённый плагин — обычно это
`ruby-lsp@claude-plugins-official`, — расширение достаётся тому, кто зарегистрировался первым, а
второй не стартует вовсе. О конфликте никто не сообщает. Лишний выключается:

```sh
claude plugin disable ruby-lsp@claude-plugins-official
```

## Грабли сервера — файл проекта, а не пакета

Текст отбоя заканчивается ссылкой на `docs/agents/ruby-lsp.md`, и этот файл принадлежит репозиторию,
а не пакету: чего сервер не резолвит, зависит от гемов проекта, от того, как у него разложены файлы,
и от того, что лежит за корнем воркспейса. Скилл `setup-ruby-lsp` кладёт туда семя, дальше файл
правит проект; второй копии пакет не держит, поэтому установка его не затирает. Пока файла нет,
текст отбоя называет вместо пути сам скилл.

Этот файл — единственный, который скилл пишет. Остальное он докладывает и ничего больше в репозитории
не меняет: ни файл инструкций, ни `Makefile` с `Gemfile`, и гемов не ставит — как проект настраивает и
описывает свои инструменты, решает тот, чей это проект.

## Разработка

```sh
test/lsp-hint_test.rb                 # весь набор
test/lsp-hint_test.rb -n /pickaxe/    # случаи по подстроке имени
```

Bundler и фреймворк не нужны: minitest берётся из поставки ruby, а хук зовётся процессом со своим
`TMPDIR`, поэтому прогон не зависит ни от приложения, ни от живых сессий.

Устройство хука и причины решений — [`hooks/lsp-hint.md`](hooks/lsp-hint.md). Охват набирался замером
в живых сессиях, поэтому набор тестов читается ещё и как перечень того, что казалось покрытым.
