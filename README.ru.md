# ruby-lsp

[In English](README.md)

Языковой сервер ruby для Claude Code: навигация по коду и его анализ.

[Официальный плагин `ruby-lsp`](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ruby-lsp) от Anthropic
ограничивается одним объявлением языкового сервера [ruby-lsp](https://github.com/Shopify/ruby-lsp), а этого недостаточно.
Системный prompt велит искать с помощью `grep`. Вдобавок инструменты LSP-сервера инициализируются лениво,
и путь поиска через них проигрывает `grep`, который есть в списке тулов с первой секунды сессии.
Из-за этого тул `LSP` вызывается агентом только если его прямо об этом попросить. Плагин решает эту проблему.

## Поддерживаемые расширения

`.rb`, `.rake`, `.gemspec`, `.ru`, `.erb`

## Установка

### Через Bundler (рекомендуется)

Добавьте в Gemfile:

```ruby
gem 'ruby-lsp', group: :development
```

Затем выполните:

```sh
bundle install
```

Установка через `bundler` позволяет держать `ruby-lsp` на той версии `ruby`, которая используется в проекте.
Если не синхронизировать их, они могут разъехаться. Падение при этом
тихое: Claude Code гасит lsp-сервер после трёх неудачных стартов и больше не поднимает.

### Через gem

```sh
gem install ruby-lsp
```

## Как это работает

Вызов тех или иных инструментов не детерминирован при агентной разработке. LLM сама решает, вызвать или нет в каждый
конкретный момент. Поэтому инструкции типа "Используй LSP" в CLAUDE.md работают плохо. Для строгого выполнения
существуют [хуки](https://code.claude.com/docs/en/hooks-guide).

### Хук на запуск Bash/Grep

Хук `PreToolUse` на запуск инструментов Bash и Grep выполняет скрипт `lsp-hint.sh`. Его цель —
определить, является ли ввод командой поиска **символов** в ruby-коде. Исходов у скрипта два: промолчать,
и тогда обычный текстовый поиск выполняется как есть, либо отклонить вызов
(`permissionDecision: deny`). В последнем случае агент получает причину отказа
с указанием на тул LSP и на `docs/agents/ruby-lsp.md`, где описаны особенности сервера в вашем проекте.

Хук `PostToolUse` после использования LSP ставит в сессии метку, которая при повторных вызовах `PreToolUse` позволяет
не проходить процедуру выбора снова и снова. Наша цель — подсказать агенту наличие LSP, и дважды этого делать не требуется.

### Что такое символ

Скрипт `lsp-hint.sh`, который определяет, что такое символ (название класса/метода/константы) должен быть максимально простым и быстрым.
Сложные эвристики или разбор синтаксического дерева команды тут недопустимы. Поэтому принято простое соглашение:
**символ — это текст без пробела**. Например, `grep User` — это поиск по
символу, который перехватывается LSP. `grep 'GROUP BY total'` — а это то, что обрабатывается обычным текстовым поиском.

## Требования

- Ruby >= 3.0 — нижняя граница самого `ruby-lsp`
- Claude Code >= 2.1.157
- APM >= 0.29.1 — для установки через APM (опционально)
- `bash` и `jq` — хук написан на bash и разбирает свой вход через `jq`

## Установка пакета

Если у вас подключен [официальный плагин `ruby-lsp`](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ruby-lsp),
требуется его отключить, чтобы исключить коллизию объявлений.

### Отключите официальный `ruby-lsp`

```sh
claude plugin disable ruby-lsp@claude-plugins-official
```

### Добавьте пакет через [Agent Package Manager](https://microsoft.github.io/apm/)

Объявите зависимость в `apm.yml`:

```yaml
dependencies:
 apm:
   - xronos-i-am/ruby-lsp
```

```sh
apm install
```

или

```sh
apm update
```

если `apm` уже залочил сборку пакетов (`apm.lock.yaml`)

### Перезагрузите плагины или откройте новую сессию

```
/reload-plugins
```

### Выполните настройку в агенте

Один раз выполните скилл `/ruby-lsp-setup`. Он проверяет корректность установки, а также добавляет инструкцию `docs/agents/ruby-lsp.md`.
В ней вы можете дополнительно описать особенности использования LSP именно в вашем проекте.

### Проверка работы

Откройте новую сессию агента и задайте промпт:

```prompt
грепни User
```

Если настройка прошла успешно, вы увидите упоминание LSP, вызов которого перебьет поиск с помощью `grep`.

## Установка плагином Claude Code

```sh
claude plugin marketplace add xronos-i-am/ruby-lsp
claude plugin install ruby-lsp@xronos-i-am --scope project
```

На этом пути скиллы называются с префиксом плагина: `/ruby-lsp:ruby-lsp-setup` и `/ruby-lsp:ruby-lsp-feedback`.

## Удаление

```sh
apm uninstall xronos-i-am/ruby-lsp
apm install
```

Второй командой здесь пренебрегать нельзя: `apm uninstall` оставляет объявление сервера. Хука нет, а сервер продолжает подниматься.

```sh
claude plugin uninstall ruby-lsp@xronos-i-am --scope project
claude plugin marketplace remove xronos-i-am
```

## Решение проблем

Если вы не видите в сессии упоминание инструментов LSP, можете для диагностики вызвать скилл `/ruby-lsp-feedback`.
Он соберет нужную информацию, которую потом можно добавить в [issues](https://github.com/xronos-i-am/ruby-lsp/issues).

## Разработка

```sh
test/lsp-hint_test.rb                 # весь набор
test/lsp-hint_test.rb -n /pickaxe/    # случаи по подстроке имени
```

Чем плачено за каждое решение и что хук пропускает намеренно — [`hooks/lsp-hint.ru.md`](hooks/lsp-hint.ru.md).
